# BuildKit Cache Invalidation Bug Test

## Summary

Added a regression test `testInlineCacheMultiStageIndependentLayers` to BuildKit that reproduces the inline cache bug where changing a file in a downstream stage incorrectly invalidates the cache for an independent upstream stage.

## Files Modified

### `frontend/dockerfile/dockerfile_test.go`

1. **Added to test list** (line 104):
   - `testInlineCacheMultiStageIndependentLayers`

2. **Added test function** (lines 10631-10746):
   - Full integration test that reproduces the bug

## Test Description

The test verifies that BuildKit's inline cache correctly handles multi-stage builds with independent layers:

```
stage1 (independent)
  ├─> RUN commands (no file dependencies)
  └─> Generates unique random file
      ↓
stage2 (depends on stage1 + dummy file)
  ├─> FROM stage1
  └─> COPY dummy (this will change)
      ↓
stage3 (final output)
  └─> COPY from stage2
```

### Test Steps

1. **Initial Build**:
   - Build with `dummy` file containing 'x'
   - Export inline cache to registry
   - Save the unique file generated by stage1

2. **Rebuild with Changed File**:
   - Prune all local cache
   - Change `dummy` file to 'y'
   - Rebuild using only inline cache
   - Read the unique file from stage1

3. **Assertion**:
   - The unique file should be **identical** in both builds
   - This proves stage1 was cached (not rebuilt)
   - **If different** → BUG: cache was incorrectly invalidated

## Expected Behavior

### On Fixed BuildKit
The test should **PASS**, with output showing:
- stage1 cached successfully
- Unique files match between builds
- Only stage2+ rebuilt due to dummy file change

### On Buggy BuildKit (v0.8.3)
The test should **FAIL** with error:
```
stage1 was rebuilt even though it doesn't depend on the changed file.
This indicates the cache incorrectly invalidated stage1
when stage2's file selector changed.
```

## Root Cause (Hypothesis)

The bug is in BuildKit's inline cache implementation:

1. **File**: `cache/remotecache/v1/cachestorage.go`
   - Method: `WalkLinks()` (lines 143-157)
   - Issue: Returns empty result set when selector doesn't match

2. **File**: `solver/cachemanager.go`
   - Method: `getIDFromDeps()` (lines 312-351)
   - Issue: Intersection logic causes empty set to invalidate cache

### The Problem

When stage2's file selector changes (dummy: x→y):
1. `WalkLinks` for stage2's dependency returns no matches
2. Intersection in `getIDFromDeps` becomes empty
3. This empty set propagates to stage1's dependencies
4. Stage1's cache lookup fails → unnecessary rebuild
